## 1. 준비

```bat
git fetch upstream
git switch feat/rag-indexing          # 또는 머지됐으면 develop
```

`backend/.env`에 아래 7개가 있어야 합니다 (따옴표 없이):
```
OPENAI_API_KEY=sk-...
EMBEDDING_MODEL=text-embedding-3-small
DB_HOST=db                 ← 로컬 리허설. 원격이면 EC2 IP
DB_PORT=5432
DB_NAME=...
DB_USER=...
DB_PASSWORD=...
```
루트 `.env`(POSTGRES_DB/USER/PASSWORD 3개)는 로컬 db 컨테이너용이라 원격과 무관합니다.

## 2. 실행 (도커 기준, 레포 루트에서)

```bat
REM .env 바꿨으면 컨테이너 재생성 (안 하면 옛날 값 씀)
docker compose up -d --force-recreate backend

REM ① 지금 DB 상태 (읽기만) — 첫 줄 DB: 가 원하는 곳인지 확인
docker compose exec backend python manage.py check_index

REM ② 청크만 뽑아서 확인 (임베딩 X, OpenAI 키 없어도 됨)
docker compose exec backend python manage.py build_index --dry-run --sample 10
REM    → 총 3839 / doc_id 중복 0  (9/13 청킹 조정 이후 기준. 9/10에는 3832)
REM    → backend/artifacts/chunks.json 생성 (청크 전체, 눈으로 검토용)

REM ③ 원격이면 여기서 채널 공지: "build_index 재적재 돌립니다, 몇 분간 검색 비정상"

REM ④ 임베딩 + 적재 (3,839건, 약 40만 토큰, 100원 안팎, 2~3분)
docker compose exec backend python manage.py build_index

REM ⑤ 들어갔는지 확인
docker compose exec backend python manage.py check_index --expect 3839
```

⑤에서 이렇게 나오면 성공:
```
총 청크: 3836  (Document 18개)
stadium_code 없음: 5
embedding NULL: 0
✔ 벡터 인덱스 있음
공식매점 청크: 0
```

## 3. 로컬 → 원격 전환

로컬에서 ④까지 성공하면 `backend/artifacts/embeddings.npy`에 벡터가 저장돼 있습니다.
`backend/.env`의 DB_HOST/NAME/USER/PASSWORD를 원격 값으로 바꾸고 ②~⑤를 다시 돌리면
**OpenAI 호출 없이** 저장된 벡터로 INSERT만 합니다 (체크포인트 지문이 같으면 재사용).

## 4. 막히는 곳

| 증상 | 원인 | 조치 |
|---|---|---|
| `No module named 'django'` | 도커 밖에서 실행함 | `docker compose exec backend …` 로 |
| `env file .env not found` | 루트 `.env` 없음 | 루트에 `.env` 만들기 (POSTGRES_* 3개). `.gitignore`에 있는지 확인 |
| `DB: db:5432/mydb` 인데 원격 기대 | `backend/.env` DB_HOST 가 db | 원격 IP로 바꾸고 `--force-recreate` |
| `password authentication failed` | 원격 계정/비번 불일치 | EC2 세팅한 사람한테 DB_NAME/USER/PASSWORD 확인 |
| `connection timed out` | 보안그룹 5432 미개방 | 내 공인 IP 인바운드 추가 |
| `AuthenticationError` / `invalid_api_key` | 키 따옴표 또는 만료 | `.env` 따옴표 제거, 새 키 |
| 총 청크가 3839 ± 200 밖 | 파일 누락/필터 오류 | `chunks.json` 파일별 개수 확인 |
