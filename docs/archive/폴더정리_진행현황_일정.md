## 4. A. 오늘(9/8) 결정·처리 완료 항목

1. ✅ **`collect_kakao_places.py` 재실행 확인** — `external_places.csv` 1008건, 구장별 최대거리 2100~2490m로 2.5km 반경 정상 반영 확인.
2. ✅ **대전 오분류 5건 처리** — 황제돈까스·하나칼국수·호야네 한식뷔페·호야김밥·이츠 5곳을 `in_stadium_flag=N`으로 보정. 카카오 place_id 기준 보정 로직을 스크립트에도 넣어서 재실행해도 유지됨.
3. ✅ **예매정책 — 팀원이 만든 244행 구조화 데이터(`kbo_ticket_policy_structured.csv`, 예매 오픈시각·매수 한도)로 최종 확정, 추가 작업 없음.** "예매안내" 일반카테고리(취소·환불·NOL존·할인 등)는 스코프 제외 결정 유지. 처음엔 "구단별 예매처 아웃링크 카드"(티켓링크/인터파크/구단별 링크 버튼 UI) 안도 검토했었는데, 팀원과 협의해서 **그냥 텍스트로 안내**하는 쪽으로 최종 정리 — 예: "예매 취소·환불 등은 구단 공식 예매처에서 확인해주세요" 수준의 일반 문구로 답변. 이 결정으로 LG·KT·삼성·KIA·롯데·NC 6개 구단의 예매처 개별 URL을 찾는 작업 자체가 불필요해짐(더 이상 할 일 아님). 두산 예매안내 원문은 버리지 않고 `docs/`에 원문만 남겨두는 정도로 충분.
4. ✅ **TVING 비공식 API 계속 사용 확정.** 대안(다음스포츠)도 결국 비공식이고, 호출 빈도도 낮아서(하루 1~2회) 리스크 대비 전환 비용이 안 맞는다고 판단.
5. ✅ **SSG 반입물품 충돌 — 인터파크 공식확인 쪽으로 확정.** 더 최근에 공식 출처를 직접 열람해서 확인한 쪽이라 신뢰도가 높음. 도수 6도 제한·몰리스 그린존 그대로 유지, 팀원 보완자료의 "팀 고유 예외 미확인" 쪽 결론은 채택 안 함.

## 4-1. 재입장 규정 — 최종 종결 (2026-09-08)

2. ✅ **질문지 발송 절차는 진행하지 않기로 팀 결정.** 원정 응원 가이드와 동일하게, 개별 공식 검증 없이 `reentry_status=PARTIAL`, `reentry_evidence_type=UNOFFICIAL`로 태깅한 "몇 월 기준" 고정데이터로 유지하기로 확정. 재입장 항목은 이걸로 완전히 마무리 — 더 이상 남은 작업 없음. (상세 근거는 `재입장규정_검증메모.md` 최종 결론 섹션 참고)

## 4-2. 전처리 마감 최종 점검 (2026-09-08 저녁) — 발견·처리한 것

내일(9/9) 청킹 시작 전에 데이터 전체를 다시 훑어본 결과:

1. ✅ **`구장먹거리,컨텐츠.xlsx`(공식 매점 284건) 전처리 공백 발견 → 처리 완료.** 카카오 데이터 등 다른 모든 원본은 진작 `data/preprocessed/` CSV로 전처리돼 있었는데, "분리하기" 정책의 다른 한 축인 이 파일만 raw xlsx 상태로 방치돼 있었다. `preprocessing/normalize_food_stores.py`를 새로 작성해 `구장먹거리_공식매점.csv`(284행)로 전처리 완료.
2. ✅ **같은 파일 안 "Attractions" 시트(구장 내부 키즈존·포토존·체험존 등 68건)도 어떤 문서에도 언급된 적 없이 방치돼 있던 걸 같이 발견** → 같은 스크립트로 `구장부가콘텐츠_공식.csv`(68행)로 전처리 완료. 이건 카카오 AT4(구장 주변 관광명소)와는 다른 데이터라서(구장 "내부" 콘텐츠) 혼동하지 않도록 파일명을 분리했다.
3. ✅ **이 두 시트의 Evidence Type이 `OFFICIAL_GUIDE_MAP`처럼 세분화된 값이던 것을 발견** — 반입물품·재입장 파일에서 있었던 것과 같은 종류의 이름 불일치. `evidence_type=OFFICIAL`(프로젝트 공통 어휘)로 정규화하고 원래 세분값은 `evidence_subtype`에 보존했다.
4. ✅ **`kbo_schedule_full.csv`에서 `stadium_code=OTHER`인 특이 케이스 3건 발견** — 삼성이 2026-05-19~21에 대구가 아닌 "포항"에서 치른 지역연고 방문경기. 우리가 추적하는 9개 구장에 포함되지 않는 곳이라 external_places·편의시설·먹거리 데이터가 전혀 없다. 챗봇이 이 3경기를 안내할 때는 "이 경기는 포항 특별경기라 주변 정보는 제공하지 않습니다" 수준으로 답하도록 별도 처리 필요 — LLM/백엔드 팀에 전달할 것.
5. ✅ **나머지 전수 점검 — 문제 없음.** 전체 CSV에 완전 중복행 없음, 인코딩 깨짐(모지바케) 없음, 9개 표준 stadium_code 외의 값 없음(위 포항 건 제외), null 값들은 전부 설명 가능한 정상 케이스(예: 전화번호 없는 장소, 아직 안 열린 경기의 스코어, 매수 제한 없는 예매정책 등).

**결론**: 오늘 밤 기준으로 데이터 자체의 결함은 없고, 위 1~4번을 처리한 게 사실상 "마지막 전처리"였다. 재입장 규정도 4-1에서 최종 종결됐다. 남은 항목(KT 반입물품 OPEN, F&B 영업시간, 포항 특별경기 예외처리 전달)은 전부 이미 알고 있던 저우선순위 항목이며 새로 발견된 문제는 아니다.
