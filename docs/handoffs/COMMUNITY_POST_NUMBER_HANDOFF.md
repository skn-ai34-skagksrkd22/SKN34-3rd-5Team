# 커뮤니티 게시글 번호 인계

## 현재 구현

게시판 목록 ‘구분’과 상세에 `006001`처럼 숫자 6자리의 `postNumber` 문자열을 표시한다. 자유·팀·승부 예측 게시판이 하나의 번호 체계를 공유한다. 연도, 게시판 접두어, 팀 코드는 붙이지 않는다.

현재 프론트에는 예시 데이터만 연결되어 있다. 실제 글 생성 API, DB 번호 발급, 관리자 검색은 미구현이며 DB에 접속하거나 테이블을 변경하지 않았다. 예시 번호를 실서비스 DB로 이관하지 않는다.

## 백엔드 구현 규칙

- 범위는 `000001`부터 `999999`까지다. DB 공통 sequence/identity로 발급한 정수를 6자리 문자열로 반환한다. 게시판별·팀별·연도별로 초기화하지 않는다.
- 끝 6자리를 잘라서 만들거나 나머지 연산으로 순환시키지 않는다. 999999에 도달하면 번호를 재사용하지 말고 신규 생성 제한 및 운영자 알림으로 처리한다. 그 전에 번호 확장 정책을 별도 합의한다.
- 생성 트랜잭션에서 번호를 확정하고 커밋 성공 후 반환한다. 롤백 등으로 발생하는 번호 공백은 허용한다.
- Django 모델·마이그레이션으로 공통 일련번호와 unique 제약을 관리한다. COUNT+1, MAX+1, 브라우저 카운터로 발급하지 않는다.
- 수정, 팀 변경, 게시판 이동, 삭제 후 복원에도 번호를 유지한다. 삭제한 번호를 재사용하지 않는다.
- 번호와 작성자, 작성일, 조회, 추천은 클라이언트가 임의 지정하지 못하게 한다. 작성자는 로그인 사용자에서 결정한다.
- 생성·목록·상세 API에 동일한 `postNumber`를 반환하고 관리자 화면에서 이 번호로 정확하게 검색하도록 한다.
- 동일 요청 재시도로 인한 중복 글 방지는 요청 식별자 기반 멱등 처리로 별도 구현한다. 번호 unique 제약만으로 중복 게시가 방지되지는 않는다.

## API 계약 제안

아래는 인계용 제안이며 엔드포인트는 담당자와 확정한다. 생성 요청에는 `board`, `teamCode`, `category`, `title`, `content`만 포함한다. 자유게시판의 `teamCode`는 null이다. `postNumber`는 읽기 전용이며 프론트는 서버에서 받은 문자열을 그대로 표시한다.

```json
{
  "id": "2",
  "postNumber": "000002",
  "board": "teams",
  "teamCode": "LG",
  "category": "응원",
  "title": "오늘 경기 응원합니다",
  "content": "게시글 본문",
  "author": "작성자 닉네임",
  "createdAt": "2026-09-13T05:00:00Z",
  "views": 0,
  "recommendations": 0
}
```

실제 API 연결 시 예시 전용 `isSample`을 제거하고 API 어댑터에서 날짜 표시를 변환한다. DB 내부 PK와 공개 번호는 별도로 유지해도 된다.

## 프론트 위치

- `frontend/lib/community-post-number.ts`: 6자리 예시 번호 포맷 및 범위 검사. 실서비스 발급기가 아니다.
- `frontend/lib/team-community.ts`: 팀별 예시 데이터의 고정 번호. 필터·정렬·연도 변경에도 번호가 바뀌지 않는다.
- `frontend/components/community-board.tsx`: 목록과 상세의 번호 표시.

## 인수 확인

동시 작성의 번호 중복 방지, 수정·이동 후 번호 유지, 삭제 번호 재사용 방지, 연도 전환 시 연속 발급, 999999 초과 시 안전한 거절, 클라이언트 번호 변조 거절, 생성·목록·상세·관리자 검색 일치를 검증한다.
