## 2. 조작적 정의

코스는 **"경기 전 식사 → 구장 → 경기 후 갈 곳"** 이다. "핫플레이스" 대신 아래 이름을 쓴다.

### 2-1. 장소 종류

| 종류 | 코드 | 포함 | 제외 |
| --- | --- | --- | --- |
| 경기 전 식사 | `FOOD` | 카카오 음식점(FD6) | 술집, 구장 안 매대 |
| 카페·디저트 | `CAFE` | 카카오 카페(CE7) — 카페·커피전문점·테마카페·디저트 | 유아 놀이시설, 만화방·보드카페(→ 실내 놀거리 도구가 담당), 구장 안 매대 |
| 주점 | `BAR` | 음식점 중 `술집`(호프·요리주점·포장마차 등) | 구장 안 매대. **운전·가족·아이 동행이면 제외** |
| 야간 명소 | `NIGHT_SPOT` | 관광명소(AT4) 중 **테마거리 · 전망대 · 도보여행(도심 산책길) · 호수** | 산 · 계곡 · 저수지 · 숲 · 도예공방 · 온천 · 수목원 · 테마파크 · 눈썰매장 · 자연휴양림 · 동물원 (밤에 닫거나 경기 후 동선에 맞지 않음) |

- **경기 후 갈 곳** = `CAFE` + `BAR` + `NIGHT_SPOT`
- 숙박·산책·실내 놀거리·편의점은 기존 `search_nearby_places` 도구(카카오 실시간 검색)가 담당한다.

### 2-2. 구장 안 매대 판정

다음 중 하나면 구장 안 매대로 보고 코스 후보에서 뺀다. (구장 안 먹거리 질문은 자리어때 데이터 `FOOD_IN` 이 담당)

1. `in_stadium_flag = Y`
2. 이름에 구장명 + "점"이 붙음: `야구장·구장·라이온즈파크·NC파크·스카이돔·랜더스필드·챔피언스필드·위즈파크·볼파크 … 점`
3. 이름에 좌석 구역이 들어감: `내야 · 외야 · 1루 · 3루`

> 이름 규칙이라 구장 밖 매장이 일부 같이 빠질 수 있다(예: "스타벅스 사직구장점"). 코스 후보가 부족하지 않아 감수한다.

### 2-3. 거리

| 종류 | 기본 반경 | 이유 |
| --- | --- | --- |
| FOOD · CAFE · BAR | 구장 도보 20분 (1.6km) | 경기 전 도착 시간과 경기 후 막차를 고려 (도보 80m/분) |
| NIGHT_SPOT | 구장 도보 30분 (2.5km) | 기존 정책 반경. 1.6km 밖이면 답변에 "도보 20분 이상" 표시 |
| 아이·어르신 동행, "퇴근하고 바로" | 1.2~1.5km | 기존 `slots.py` 규칙 유지 |

### 2-4. 선정 방식

**조건으로 거르기 → 남은 곳 중 랜덤 → 코드가 계산한 사실로만 이유 작성**

- 추천 이유에 "맛있는 · 유명한 · 인기 많은 · 핫한" 같은 표현을 쓰지 않는다. 근거 데이터가 없기 때문이다.
- 이유는 "구장 가는 길 · 도보 4분", "일식 원하셔서"처럼 계산된 사실만 쓴다.
- 시연·평가 때는 `COURSE_SEED` 로 결과를 고정한다.

**눈에 띄는 점**
- **주점은 사실상 비어 있다** (잠실·대구·창원 0곳). 경기 후 주점 코스를 약속하려면 재수집이 필요하다 → 4-1.
- **대구는 야간 명소가 2.5km 안에 1곳뿐**이다. 대구 경기 후 코스는 카페 위주가 된다.
- 고척은 음식점 45곳 중 매대가 많아 식사 후보가 14곳으로 줄어든다.

## 4. 해야 할 일

### 4-1. 이번 범위 (정의 적용)

1. `course/agent.py` `pick()` 에 2-1 · 2-2 필터 반영 (지금은 이름에 "야구장"이 있는 음식점만 제외)
2. `SEARCHES` 의 `SPOT` 을 `NIGHT_SPOT` 조건으로 제한
3. `BAR` 가 0곳인 구장은 경기 후 코스를 카페·야간 명소로 대체하고 "주변 주점 정보가 부족해요" 한 줄
4. 수집 보강: 카카오 **키워드 검색**("호프", "술집", "포차")으로 주점만 따로 받아 45건 제한 우회
5. `collect_kakao_places.py` 반경을 정책값(2.5km)과 맞추기
6. README "코스 장소 선정 기준" 절에 2장 표를 그대로 넣기 (반영 완료)

### 4-2. 향후 과제 (인기 신호)

| 방법 | 내용 | 비고 |
| --- | --- | --- |
| 우리 사이트 코스 담기 수 | 커뮤니티에서 많이 담긴 장소를 조금 더 자주 뽑는 가중치 | 데이터가 쌓여야 함 |
| 공공 관광 데이터 | 한국관광공사 TourAPI 등의 관광지 정보로 야간 명소 보강 | 프론트에 `tour-api` 라우트가 이미 있음. 인기 지표 제공 여부는 확인 필요 |
| 사용자 별점 · 한줄평 | 코스 카드에서 직접 평가 | 처음엔 비어 있음 |
| 카카오맵 후기 링크 | 카드에 "카카오맵에서 후기 보기" | 무료, 우리 화면에 별점은 안 뜸 |
| 포털 페이지 크롤링 | — | 약관 위험, 쓰지 않음 |

## 5. 자주 받는 질문

- **핫플 기준이 뭐예요?** → "핫플"이라고 부르지 않고, 경기 후 시간대에 갈 수 있는 카페·주점·야간 명소를 도보권 안에서 고릅니다. 산·계곡·도예공방과 구장 안 매대는 뺐어요.
- **인기 있는 곳인지는 어떻게 알아요?** → 지금은 모릅니다. 평점·리뷰 데이터가 없어서 인기라고 말하지 않고, 거리·동선·요청 조건으로만 고릅니다. 인기 신호는 향후 과제예요.
- **왜 음식점이 구장 바로 앞 가게뿐이에요?** → 카카오 API가 가까운 45곳만 줘서 그래요. 구장 안 매대를 빼고, 주점은 키워드 검색으로 따로 받을 예정입니다.
