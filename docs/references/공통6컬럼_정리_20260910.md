# `content` 컬럼 보강 정리 (2026-09-10)

브랜치 `feat/common-columns` · 스크립트 `backend/preprocessing/add_common_columns.py`

## 0. 결정

팀 공통 6컬럼 `{id, source, team, category, updated_at, content}` 중 **content 만** CSV에 채운다.
나머지 5개는 `build_index`가 인덱싱 때 metadata로 이미 만들고 있어, CSV에도 넣으면 두 군데서 관리하게 되고
기존 컬럼(source_id·verified_at·team_code 등)과 의미가 겹쳐 더 어지러워진다. 필요해지면 스크립트의
`ADD_COLUMNS`에 추가하면 같은 규칙으로 채워진다.

## 3. content 규칙

`build_index.py`의 `row_text`와 **완전히 같은 규칙**:

```
[구장명 · 팀명] 컬럼명: 값 / 컬럼명: 값 / …
```
- 관리용 컬럼(source_id·source_url·verified_at·status·evidence_type·record_id·좌표 등 `SKIP_IN_TEXT`)은 문장에 넣지 않음
- 빈 값은 건너뜀
- status 가 CONFIRMED / CONFIRMED_OFFICIAL 이 아니면 끝에 `(공식 확인 전 정보로 정확하지 않을 수 있습니다.)`
- external_places 의 구장 내 매장(in_stadium_flag=Y)은 `(카카오 지도 기준 정보로 영업시간·폐업 여부 확인이 필요합니다.)`

예)
```
[대구 삼성 라이온즈 파크 · 삼성 라이온즈] team_code: SAMSUNG / stadium_code: DAEGU / access_code: PARKING_MAIN_UNDERGROUND / mode: PARKING / title: … / parking_spaces: 1117
```

## 4. 검증 결과

- content = `build_index.build_chunks()` 청크 문장과 **2,582 / 2,582건 동일** (임베딩 대상 전 행). 청크에 없는 8건은 잠실 등 구장 내 카카오 매장으로 build_index 가 의도적으로 제외하는 행.
- 기존 컬럼: 15개 파일 모두 값·순서 변경 0. content 는 마지막 컬럼.
- `build_index`는 `content`를 `SKIP_IN_TEXT`로 무시하므로 **인덱싱 결과 불변**.
